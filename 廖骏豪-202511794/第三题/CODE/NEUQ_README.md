## 二、引脚与接线（当前配置，全部在 `NEUQ_Config.h` 里可改）

### 2.1 本题用到的引脚

| 功能 | 宏 | 引脚 / 外设 | 说明 |
|------|----|-------------|------|
| 电机 PWM（EN） | `NEUQ_MOTOR_PWM_PORT` | **PA2 = TIM2_CH3** | 占空比 = 转速，8.4 kHz |
| 电机方向（PH） | `NEUQ_MOTOR_DIR1_PORT` | **PA4 = GPIO 输出** | 高/低电平 = 转向（实测 PA4 有效） |
| 双 PWM 备用脚 | `NEUQ_MOTOR_PWM2_PORT` | PA5 = TIM2_CH1 | PH_EN 模式不用 |
| 驱动模式 | `NEUQ_MOTOR_MODE` | `NEUQ_MOTOR_MODE_PH_EN` | DRV8701 的 PH/EN |
| 编码器 A 相 | `NEUQ_ENCODER_PHASE_A` | **PB6 = TIM4_CH1** | 正交编码器，库内 TI12 四倍频 |
| 编码器 B 相 | `NEUQ_ENCODER_PHASE_B` | **PB7 = TIM4_CH2** | |
| 上位机串口 | `NEUQ_COMM_UART` | **USART1 = 库里的 `UART_0`** | PA9=TX / PA10=RX，115200 8N1 |
| 控制节拍 | `NEUQ_PIT_CHANNEL` | **TIM6（`PIT_CH1`）** | 5 ms / 200 Hz |

### 2.2 定时器占用（无冲突）

| 定时器 | 用途 |
|--------|------|
| TIM2 | 电机 PWM（CH3 → PA2） |
| TIM4 | 编码器正交解码（PB6 / PB7） |
| TIM6 | 控制节拍 5 ms |

### 2.3 驱动板接线（DRV8701E，PH/EN 模式）

| 驱动板信号 | MCU 引脚 | 说明 |
|------------|----------|------|
| `PWM_1_IN` → DRV8701 的 **EN** | PA2 | 占空比 = 转速 |
| 方向 → DRV8701 的 **PH** | PA4 | 电平 = 转向（实测 PA5 不行） |
| 编码器 A | PB6（板上丝印的 A/B 可能相反） | 接反只影响计数方向，用 `NEUQ_ENCODER_DIR_SIGN` 修正 |
| 编码器 B | PB7 | |
| 编码器供电 | 3.3V / 5V + GND | **必须与主板共地** |
| 串口 | PA9 / PA10 | 接板载 ST-Link 虚拟串口（设备管理器里的 COM 口） |

> **注意**：串口用 ST-Link 虚拟串口时，USART1 是直接焊在 ST-Link 上的，不需要飞线；
> 主板右下角那个 3 芯「串口」座走的是 PC10/PC11 = UART4 = 库里的 `UART_3`，**不要选错**。
>
> **刹车说明**：DRV8701 的 PH/EN 模式没有短接制动能力——EN 拉低就是 H 桥全关、电机自由滑行，
> 所以 `NEUQ_STOP_BRAKE` 对本模式无效（填 0），闭环运行时输出过零也是滑行，不会在零速附近顿挫。

### 2.4 编码器换算

```
每输出轴一圈计数 = PPR × 倍频 × 减速比 = 13 × 4 × 30 = 1560
转速(RPM) = 计数增量 × 60 / (1560 × 0.005s)
```
即 1 个计数 ≈ **7.69 RPM**（5ms 周期），这也是低转速时会有量化台阶的原因。

## 三、软件结构（为什么通信不会打断控制）

```
              主循环（可以是任意耗时）                      5ms 定时中断（短、定长）
  ┌──────────────────────────────────────────┐   ┌──────────────────────────────────────┐
  │ NEUQ_Comm_Poll()                          │   │ NEUQ_Control_ISR()                   │
  │   串口字节中断 → 环形缓冲 → 状态机解包     │   │   ① 取指令邮箱（启停/目标/PID）       │
  │   解包成功 → NEUQ_Control_ReqXxx() ───────┼──▶│   ② NEUQ_Speed_Update() 读编码器测速  │
  │                                          │   │   ③ NEUQ_Pid_Update() 算输出          │
  │ NEUQ_Comm_Upload()                        │   │   ④ NEUQ_Motor_SetOutput() 写 PWM     │
  │   取快照（关中断拷贝） → FireWater 文本 ───┼◀──│   ⑤ 更新快照                          │
  └──────────────────────────────────────────┘   └──────────────────────────────────────┘
```

* **闭环只在中断里跑**：不管上位机是否连着、发了多少命令，5ms 节拍永远照跑。
* **串口接收中断（优先级 5）高于控制中断（优先级 6）**：控制中断里的浮点运算可以被打断，
  115200 下每字节只有 87µs，这样不会因为控制计算而丢字节。
* **指令邮箱**：主循环把「期望状态」写进结构体，最后才 `seq++`；中断发现 `seq` 变化才整组取用，
  不会取到半套参数。
* **回传快照**：中断写、主循环关中断拷贝，保证一帧里 7 个通道来自同一个控制周期
  （不会出现「新目标配旧转速」）。

## 四、上位机 → 下位机　字节包帧格式

```
0xAA 0x55  CMD  LEN  DATA[LEN]        ← 通用帧头
0xCC 0xDD  CMD  LEN  DATA[LEN]        ← 轻量帧头（等价，专给 VOFA+ 滑条用）
```

* **不带校验字节**。原因：VOFA+ 命令/滑条的占位符 `%%` 是**发送时**才替换成 4 字节小端 float 的，
  CRC 无法预先算好，带校验时滑条永远发不出合法帧。帧长只有几字节、115200 短距离通信，
  再加上「非法长度丢弃 + 半帧 50ms 超时重同步」，实际足够可靠。
* 多字节一律**小端**，`float` 为 IEEE754 单精度。
* 状态机逐字节解析：**一帧分几次到达、多帧连续到达都能正确解包**；
  数据域**收满最后一个字节的当拍就分发**（这一点很关键：等下一个字节再分发会导致
  单条命令迟迟不生效、连续帧丢帧头）。
* 走 `CC DD` 还是 `AA 55` 完全等价，解析器两种帧头都认。

| CMD | 含义 | LEN | DATA |
|-----|------|-----|------|
| `0x01` | 设置 PID 参数 | 12 | `float kp, float ki, float kd` |
| `0x02` | 设置目标转速 | 4 | `float 目标转速(RPM)`，限幅 0~300（只正转，负值按 0） |
| `0x03` | **启动闭环** | 0 | —（自动退出开环模式） |
| `0x04` | **停止** | 0 | — |
| `0x05` | 辅助增益（可选） | 8 | `float kff（前馈）, float slew（每周期输出最大变化量，0=不限）` |
| `0x06` | 清 PID 积分/内部状态 | 0 | — 不影响启停 |
| `0x07` | 立即回传一帧 | 0 | — |
| `0x08` | 开环调试占空比 | 4 | `float -10000~10000`（负值同样被钳到 0），会自动退出闭环 |
| `0x11` | 单参数：只改 **Kp** | 4 | `float Kp`（专给 VOFA+ 滑条） |
| `0x12` | 单参数：只改 **Ki** | 4 | `float Ki` |
| `0x13` | 单参数：只改 **Kd** | 4 | `float Kd` |
| `0x14` | 运行时改**测速方向符号**（排查正反馈飞车用） | 4 | `float ±1.0` |

**行为约定**

* 上电 = **停止 + 目标 0 + 默认 PID**，必须收到 `0x03` 才动（题目要求「上电等待启动命令」）。
* 运行中随时可以改目标（`0x02`），曲线立刻跟随。
* PID 参数在停止和运行中都接受（题目要求「停止状态可修改」，这里做成超集，方便边跑边调）。

**示例（轻量帧，VOFA+ 的 Hex 模式直接粘贴）**

```
启动          CC DD 03 00
停止          CC DD 04 00
目标 100 RPM  CC DD 02 04 00 00 C8 42
目标 200 RPM  CC DD 02 04 00 00 48 43
PID 20/3/0    CC DD 01 0C 00 00 A0 41 00 00 40 40 00 00 00 00
```

## 五、下位机 → 上位机　回传（FireWater 文本，7 通道）

每 **4 个控制周期（20ms / 50Hz）** 回传一行，收到命令后再额外插一次立即回传：

```
目标, 实际, Kp, Ki, Kd, 输出, 使能\r\n
例：100.00,99.81,20.00,0.00,0.00,3333.3,1
```

| 通道 | 内容 | 说明 |
|------|------|------|
| i0 | 目标转速(RPM) | 当前生效的目标（关斜坡时等于下发值） |
| i1 | 实际转速(RPM) | 编码器测速（已一阶滤波） |
| i2 | Kp | 当前**实际使用**的值 |
| i3 | Ki | |
| i4 | Kd | |
| i5 | 输出 | 0~9000（只正转），可直接看出是否顶到限幅 |
| i6 | 使能 | 1 = 闭环运行中，0 = 停止 |

* 通道顺序与 `NEUQ_UPLINK_WITH_STATE` 一一对应，改配置就会自动变成 5 通道。
* 文本帧比二进制长，所以回传频率降到 50Hz（115200 下占用约 2KB/s，很小）。
* 回传的 PID 是**实际生效值**，不是下发的原始值；收到命令后等一拍再发，保证
  「上位机显示值 = 单片机正在用的值」。
* 若确实需要二进制：把 `NEUQ_UPLINK_MODE` 改成 `NEUQ_UPLINK_MODE_VOFA`（JustFloat）
  或 `NEUQ_UPLINK_MODE_FRAME`（`AA 55 81 LEN DATA`），通道顺序完全一致。

## 六、控制实现（对应评分点的做法）

| 评分点 | 做法 |
|--------|------|
| **稳态误差** | 位置式 PI（按参考实现对齐）：`Ki=3` 每拍累加、Σe 限幅 20000，0.2~0.5 s 把静差积掉；默认 Kp=20 / Ki=3 / Kd=0 |
| **超调量** | ① 积分分离（误差 >200RPM 才暂缓积分）；② **输出限幅回算**抗饱和（顶到限幅就把积分改写成刚好不越界的值，升降速两个方向都不会积在饱和外面）；③ 微分先行（对测量值微分，目标阶跃不产生微分冲击）；④ 可选输出变化率限幅 `slew` |
| **响应时间** | 误差一出现比例项立刻有输出；`Ki` 取到 150 使 100RPM 阶跃约 0.6~0.8s 进 ±2%；需要更快可用 `0x05` 给速度前馈 `kff≈33` |
| **扰动恢复** | 位置式积分持续作用，负载去掉后自动把转速拉回目标 |
| **单位换算** | `RPM = 计数增量 × 60 / (13×4×30 × 0.005)`，1 计数 ≈ 7.69 RPM |
| **定周期** | TIM6 5ms 中断里完成「读编码器 → PID → 写 PWM」，无等待、无打印 |
| **启停** | 上电 `enable=0`、PWM=0、PH 拉低；启动时复位调节器从 0 平滑起步；停止时清积分并关断输出 |
| **通信不打断控制** | 见第三节的数据流 |

## 八、验收步骤

### ① VOFA+ 设置（这一步错了就看不到曲线）

| 项目 | 值 |
|------|----|
| 数据引擎 / 数据格式 | **FireWater**（不是 JustFloat，也不是 RawData） |
| 通道数 | **7** |
| 波特率 | **115200** |
| 串口 | 板载 ST-Link 虚拟串口（COM9/COM10 之类） |
| DTR / RTS / 流控 / Break | **全部关闭** |
| 命令 | 全部切 **Hex** 模式 |

上电自检：i0=0、i1=0、i2=20、i3=150、i4=0、i5=0、i6=0，**电机不转**。

### ② 开环确认接线与测速方向

```
CC DD 08 04 00 00 FA 44     开环 +2000（20% 占空比）
```
电机应转，i1 应为**正数**；符号不对就把 `NEUQ_ENCODER_DIR_SIGN` 取反；
转向与定义相反就改 `NEUQ_MOTOR_DIR_SIGN`（**两个符号只能改一个**）。

```
CC DD 08 04 00 00 00 00     退出开环
```

### ③ 整定 PID（停止状态下发，也可运行中改）

```
CC DD 04 00                                        停止
CC DD 01 0C 00 00 A0 41 00 00 40 40 00 00 00 00    PID 20/3/0（默认，先只用 P）
```
整定顺序：先 `Ki=3, Kd=0`，加大 `Kp` 到转速略有过冲，再退回 60%~70%；
再加 `Ki`（从 50 开始往大调到不拖尾、不振荡）；`Kd` 一般给 0。

### ④ 闭环运行 + 升降速

```
CC DD 02 04 00 00 48 43     目标 200
CC DD 03 00                  启动
CC DD 02 04 00 00 16 43      → 150
CC DD 02 04 00 00 C8 42      → 100
CC DD 02 04 00 00 70 42      → 60
```
观察 i0 / i1 两条线：i1 应紧跟 i0，超调小、响应快。

### ⑤ 扰动恢复

运行中用手捏轮子加负载再松开 → i1 先下跌、随后回到目标值。

### ⑥ 连续运行 ≥30 s

期间反复下发目标、启停、改 PID → **i1 曲线不得中断**。

### ⑦ 停止

```
CC DD 04 00
```
电机停（DRV8701 PH/EN 是滑行），i6 回 0。

> 完整可复制的指令表见 `Docs/电机控制指令速查.md`，现场照着念的版本见 `Docs/验收操作卡.md`。

## 十、常见问题

| 现象 | 原因 / 处理 |
|------|-------------|
| 上电电机就转 | 接线错或方向脚接反；本工程上电占空比固定 0、PH 拉低，不会主动转 |
| 转速一直是 0 | 编码器没接 / 没共地；或编码器接到了别的定时器（改 `NEUQ_ENCODER_DEV/PHASE_A/PHASE_B`） |
| 改小目标反而冲到最大 / 越刹越猛 | 典型症状：降目标时电机反向全速、输出顶死。原因是编码器分不清方向时还允许负输出（不可观测分支）。现在 `NEUQ_MOTOR_ALLOW_REVERSE=0`，输出钳在 0~9000，负输出按 0（滑行），不会再出现 |
| 转速数值差 10 倍 | 减速比填错：13 线 × 4 × 减速比，本机 `NEUQ_ENCODER_GEAR = 30` |
| 转速抖动大 | 编码器 13 线分辨率低（1 计数≈7.7RPM），可加大 `NEUQ_SPEED_FILTER_ALPHA` 或降低目标 |
| 输出长时间顶在 9000 | 目标超过物理转速（约 300 RPM）时 PID 会一直顶满，属正常限幅；把目标降下来即可 |
| VOFA+ 不出曲线 | 数据格式必须选 **FireWater**、通道数 **7**、波特率 **115200**、串口选 ST-Link 的 COM 口 |
| 曲线是一行行文字 | 数据格式选成了 RawData/文本，改成 FireWater 即可 |
| 发命令没反应 | 命令是否切了 **Hex** 模式；内容别带 BOM；`LEN` 与实际数据字节数要一致 |
| 想换串口 | 改 `NEUQ_COMM_UART` **并同步改** `NEUQ_COMM_UART_INDEX`（0=USART1 … 3=UART4），中断回调靠这个宏转发 |
| 想提高控制频率 | 改 `NEUQ_CONTROL_PERIOD_MS`（注意编码器在大转速下 16 位计数会更快溢出，5ms 是安全值） |
| **电机在转但 i1 一直是 0** | ① 查编码器供电、共地（不共地是最高频原因）；② 手慢慢转轮子，万用表量 PB6/PB7 对 GND 应有 0↔3.3V 跳变（`NEUQ_Speed.c` 已给这两脚加了内部上拉，开漏编码器也能读到）；③ 两脚都不跳 → 编码器没供电/线断/坏；④ 现在 PWM 在 **PA2(TIM2)**、**TIM3 空闲**，若怀疑编码器接在另一组口，可把第 3 小节改成 `Encoder_TIM3 / Encoder_TIM3_PhaseA_PA6 / Encoder_TIM3_PhaseB_PA7` 试；⑤ 若 PB6/PB7 有跳变但 i1 仍为 0，说明那两根线没真正进 TIM4 通道，核对接线 |
